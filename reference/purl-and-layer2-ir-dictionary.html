01ECMA-427 PURL 8 大核心生态规范化速查表

通用规则：pkg:<type>/[namespace/]<name>[@version][?qualifiers][#subpath]；scheme 与 type 恒小写；qualifiers 键小写、剔除空值并按字典序排序；解析顺序从右向左。

生态 type namespace 规则 name 与大小写归一化 匹配关键 Qualifiers 规范示例与工程踩坑备忘
maven 必填（groupId，保留点号与大小写） artifactId，大小写敏感，原样保留 classifier、type / packaging pkg:maven/org.apache.logging.log4j/log4j-core@2.14.1
区分 sources / tests / shaded 构件须保留限定符。
npm 可选（Scoped 包 @org，小写） 小写；遵循 npm 命名规范 通常无需（剥离 repository_url） pkg:npm/%40angular/core@17.3.0
必坑：scope 中的 @ 必须百分比编码为 %40。
pypi 不使用（留空） 小写；按 PEP 503 将 _、. 及连续 - 折叠为单个 - 通常无需 pkg:pypi/django-rest-framework@3.14.0
必坑：不做 PEP 503 折叠会导致跨工具去重分裂。
golang 必填（模块路径前缀，规范强制小写） 模块主名，规范强制小写；#subpath 保留大小写 通常无需 pkg:golang/google.golang.org/genproto#googleapis/api
必坑（#308）：IR 证据层须保留原始 raw_name 兼容大写 Go 仓库。
cargo 不使用（留空） Rust crate 名，大小写敏感（常规小写） 通常无需 pkg:cargo/serde@1.0.210
Cargo 中 - 与 _ 在代码引用期可映射，但 crates.io 索引以原名为准。
deb 发行商（小写：debian / ubuntu） 源码或二进制包名（小写） distro、arch、epoch、upstream pkg:deb/debian/curl@7.88.1-10%2Bdeb12u5?arch=amd64&distro=debian-12
红线：版本中的 + 按 ECMA-427 规范编码为 %2B；L3 匹配键绝不可剥离 distro，否则 Backport 补丁全误报。
rpm 发行商（小写：redhat / fedora / rocky） RPM 包名（区分大小写，主流小写） distro、arch、epoch、upstream pkg:rpm/redhat/openssl@3.0.7-24.el9?arch=x86_64&distro=rhel-9.3
留意 epoch 与模块流（modularitylabel）上下文。
huggingface 模型组织或作者（如 distilbert） 模型仓库名 私有仓时附 repository_url pkg:huggingface/distilbert/distilbert-base-uncased@043235d6...
AI-BOM 要点：@version 锚定小写 Git Commit SHA。

02Layer 2 统一 IR 核心数据字典（PostgreSQL 双层身份架构）

表名与层级 核心主键与索引 核心字段与枚举约定 架构职责与演进定位
canonical_components
Tier 1 · 全局规范层		 PK: id (UUID)
UK: match_key
IDX: (base_purl, ecosystem)		 match_key（含匹配限定符的规范 PURL）、base_purl（无版本前缀）、ecosystem、version、component_type（library | application | operating-system | ml-model | data | service）、cpe_aliases TEXT[] 全平台唯一组件注册表。与 Layer 3 漏洞/许可/恶意包库直接挂接；0-day 爆发时通过 base_purl 实现跨万仓毫秒级反查。
snapshot_nodes
Tier 2 · 快照节点层		 PK: (snapshot_id, node_ref)
IDX: (canonical_id, snapshot_id)		 node_ref（对齐 CycloneDX bom-ref）、canonical_id、scope（required | optional | excluded）、is_direct、min_depth、occurrences JSONB（[{location, line, oci_layer, raw_purl, extractor}]）、ext_metadata JSONB 承接同一组件在多路径/多 Scope/多容器层中的独立实例；ext_metadata 预留 callstacks（L4 可达性）、ai_card（ML-BOM）与 citations 槽位。
snapshot_edges
Tier 3 · 有向关系层		 PK: (snapshot_id, src_node_ref, dst_node_ref, relation_type)
IDX: (snapshot_id, dst_node_ref)		 src_node_ref、dst_node_ref、relation_type（depends_on | provides | contains | trained_on | fine_tuned_from）、edge_scope、constraint_expr（原始声明版本范围） 完整还原直接/传递依赖树、容器/Fat-JAR 包含关系、CycloneDX provides 及 AI 训练血缘；constraint_expr 为 Phase 2 无破坏性升级求解器供数。
vex_statements
L4 降噪挂接表		 PK: id (UUID)
IDX: (asset_id, canonical_id, vuln_id)		 vuln_id（CVE/OSV/GHSA）、canonical_id、node_ref（可选精准位点）、state（not_affected | affected | fixed | under_investigation）、justification（如 vulnerable_code_not_in_execute_path）、author / source 将静态可达性、运行时裁剪与安全人工审计结论沉淀为可审计的 VEX 声明，跨快照持续继承，导出时无缝嵌入 CycloneDX VEX / OpenVEX。
