01OSV Schema v1.7.0 核心字段与三元关系语义速查（Lesson 0007）

字段 / 关系键 规范定义与取值约束 Layer 3 图谱处理语义 头号红线与工程防坑
aliases[] 等价漏洞 ID 列表（如 GHSA-* ↔ CVE-*） 建立对称 ALIAS_OF 边，通过并查集聚为同一 canonical_group，报告去重合并计数。 严禁写入 DSA / USN！发行版 Backport 修复版本号低于上游，混入别名会传染未修区间引爆误报。
upstream[]
v1.7.0 新增		 有向衍生溯源（如 DSA-5615-1 → CVE-2024-21626） 建立有向 UPSTREAM_OF 边；UI/工单折叠归档至主 CVE 卡片，匹配区间按发行版独立求值。 不可反向将上游区间覆盖到发行版规则上；匹配键必须保留 distro 限定符隔离。
related[] 同源或配套漏洞弱关联列表 建立 RELATED_TO 边；仅作关联超链接跳转参考，不做等价合并。 不共享影响区间，也不参与跨记录风险分数合并折算。
affected[].ranges[] type: SEMVER | ECOSYSTEM | GIT + events[]（introduced / fixed / last_affected / limit） "introduced": "0" 表示自首个版本即受影响；同一 ranges[] 多事件按时间线配对开闭区间。 注意 last_affected 为闭区间上界（≤），fixed 为开区间上界（<），禁止混为一谈。
withdrawn RFC 3339 撤销时间戳（墓碑标记） 保留 raw_advisories 记录但冻结下游匹配规则（is_enabled=false），发 intel.advisory.updated 消警。 严禁物理 DELETE，否则滞后 NVD 同步时会令假 CVE 复活并破坏历史审计链。
ecosystem_specific vs database_specific 生态官方扩展（如 Go imports[].symbols）vs 各数据源私有属性（如 GHSA github_reviewed） ecosystem_specific.imports 直接供给 Phase 2 函数级可达性索引；github_reviewed 驱动字段权威权重。 禁止强依赖非标准 database_specific 私有字段结构而不做空值降级。

03跨生态原生版本排序、VERS 与 Backport 隔离速查（Lesson 0008）

生态 / 规范 语法骨架 全序链与特殊符号优先级 核心工程防坑与嵌入库选型
SemVer / npm / Go MAJOR.MINOR.PATCH[-pre][+build] 1.0.0-1 < 1.0.0-alpha < 1.0.0-rc.1 < 1.0.0 == 1.0.0+build；Go 伪版本按 UTC 时间戳排 L3 禁止直接用 node-semver <fixed（会漏报预发布版）；Go x/mod/semver 需 v 前缀而 OSV 禁 v。
Apache Maven
ComparableVersion		 . 项分隔；- 与数字/字母切换生子表 alpha/a < beta/b < milestone/m < rc/cr < snapshot < ""/ga/final/release < sp < 未知词 < .1 1-alpha-1 == 1.0.0-alpha-1；1.0-redhat-00001 > 1.0（未知修饰符排在正式版后）。
Python PEP 440 [N!]N(.N)*[{a|b|rc}N][.postN][.devN][+local] 1.0.dev1 < 1.0a1.dev1 < 1.0a1 < 1.0 < 1.0+local < 1.0.post1 < 1!0.1 SpecifierSet('<1.0.0') 即便 prereleases=True 也拒匹配 1.0.0a1；L3 须用全序 Comparator。
Debian EVR
deb-version(7)		 [epoch:]upstream[-debian_revision] ~~ < ~ < [空] < 字母(A-Za-z) < 非字母(+ / .) 严禁跨命名空间比上游：去 Epoch 导致 DSA-5724-1 误报；带 Epoch 1: 比上游隐式 0: 导致漏报！
RPM EVR
rpmvercmp		 [epoch:]version[-release] ~ < [空] < ^ < 下一小版；分段比时数字恒大于字母；耗尽前缀时较长串胜 ~ 标预发布，^ 标后发布快照；RHEL 9 Backport 消费 CSAF VEX（如 RHSA-2024:4312）而非上游区间。
Alpine apk N(.N)*[a-z][_suffixN][-rN] _alpha < _beta < _pre < _rc < [无] < _cvs < _svn < _git < _hg < _p，最后比 -rN 1.0.0_rc1-r9 < 1.0.0-r0；主核心 Go 嵌入式选型：osv-scalibr/semantic + grype/version（全 Apache-2.0）。
VERS 标准
package-url/vers-spec		 vers:<scheme>/<c1>|<c2>|... 允许 = / != / < / <= / > / >= / *；必须按生态全序升序排列 三条规范铁律：① 零空白符；② 版本串全局唯一不重复；③ 重叠/相邻区间先合并化简（算法参考 Apache/MIT aboutcode-org/univers）。

04离线分发、签名逻辑增量链与双模高并发匹配索引（Lesson 0009）

交付层级 / 场景 物理存储与协议选型 核心工程设计机制 头号红线与商用避坑
Trivy DB 对标
（aquasecurity/trivy-db）		 go.etcd.io/bbolt（B+Tree）+ metadata.json；OCI Artifact（db.tar.gz ~90–125 MB） 桶结构 vulnerability / advisory-detail / data-source；支持 NextUpdate 限频与 Cosign 验签。 trivy.db 不是 SQLite；无原生逻辑增量（全层重拉）；商业平台禁直接镜像 ghcr.io/aquasecurity/trivy-db。
Grype DB v6 对标
（anchore/grype）		 SQLite3 + Zstd（.tar.zst ~65 MB / 解压 ~1.6 GB）；v6/latest.json Handle + Blob 解耦：affected_package_handles / vulnerability_handles 指向去重 JSON blobs，内置 KEV/EPSS。 不可裸解压覆盖，须走 grype db import <archive.tar.zst> 重建 import.json 与索引；高并发万级组件云端热路径不宜直接单条查 SQLite。
断网私有化分发与增量同步
（Air-Gap Track）		 OCI Artifact（tar+zst，复用内网 Harbor）+ Ed25519 / 离线 TUF 签名逻辑增量（pb.zst） Weekly Base + Daily Delta（~200–500 KB）：头带 prev_state_sha256 与 target_state_sha256，在 staging.db 原子重放。 严禁用 bsdiff 对 B+Tree 做二进制差分（页分裂致膨胀）；断链缺块必须熔断回退 Base；离线 Cosign 需先 cosign initialize。
withdrawn 撤回同步
（防复活闭环）		 增量载荷 tombstones[] + 逻辑状态位 is_enabled = false 标记撤回时间戳 withdrawn_at，同步推事件收敛存量工单（RESOLVED_WITHDRAWN）。 严禁物理 DELETE，否则内网滞后 NVD 镜像下次同步时会令假 CVE 重新复活。
Cloud 高并发内存匹配引擎
（10,000+ 组件 / 扫）		 纯 Go atomic.Pointer[ImmutableVulnSnapshot] + PkgKey 哈希（~120–220 MB） 四级快路径：① 规范化 PkgKey ~40ns 跳过 90%+ 洁净包；② 构建期预解析 Intervals；③ 无锁指针热换；④ 命中后异步富化描述。 禁在热路径现场正则拆解版本或用全局 RWMutex 清库重建；PkgKey 必须保留 Scope 与 DistroQualifier 隔离。
0-day 秒级应急重算
（十万级存量资产）		 PkgKey → RoaringBitmap[AssetVerID] 倒排索引（Apache-2.0） 新 CVE 到来时先查倒排位图筛出 ~0.3% 受影响资产集合，再纯内存求值区间，<10 ms 完成应急定界。 严禁从 PostgreSQL 全量拉出十万份 SBOM 重跑全量扫描；配合 Lesson 0006 Hyades 事件流驱动消警/告警。

05SPDX 语法树、三维传染性推理与商用许可证合规引擎速查（Lesson 0010）

维度 / 规则域 规范标准与优先级 核心推理规则 头号红线与工程防坑
SPDX 三层真值
（CycloneDX 1.7 / SPDX 3.0）		 Declared / Observed / Concluded acknowledgement: "declared"（清单）→ 文件头扫描 + ClearlyDefined + ORT curations.yml → concluded。 JSON 中 expression 须与 license 同级，不可嵌套进 license；不可仅靠 declared 放行夹带 GPL 包。
SPDX 运算符优先级
（Annex B）		 + > WITH > AND > OR
运算符强制全大写		 OR 选低风险最优分支并剪枝；AND 合并两侧义务并校验 OSADL/FSF 双向互斥；WITH 原子绑例外。 LGPL-2.1-only OR BSD-3-Clause AND MIT 等价于 OR(LGPL, AND(BSD, MIT))，禁扁平子串拦截。
三维上下文传染矩阵
（Dist × Link × Scope）		 dev/test 剪枝；SaaS vs Binary；Static / Dynamic / IPC dev 非分发先剪枝；MPL/EPL 仅文件级弱传染；GPL + WITH Classpath 免链接传染；AGPL §13 连 SaaS 也传染。 Go/Rust/Webpack 暗坑：单文件静态链接 LGPL-2.1/3.0 无法替换库，必须提供 .o 重链接文件或拦截！
FSF / OSADL 双向互斥对 有向兼容图
compat(In, Out)		 Apache-2.0 ↔ GPL-2.0-only 冲突；Apache-2.0 → GPL-3.0-only 单向兼容；GPL-3.0 + AGPL-3.0 经 §13 升格为 AGPL。 GPL-2.0-only 与 GPL-3.0-only 亦互斥（须 -or-later 才可升级）。
底座 / 交付环节 代码 / 数据许可 平台工程集成定位 商业闭源边界与交付规范
Go Core 内核组件
go-spdx · tools-golang · licensecheck		 代码：MIT / Apache-2.0 / BSD-3-Clause 毫秒级解析 SPDX AST、校验官方 ID 并快速分类根目录 LICENSE 原文（服务 MCP/Hook/Cloud）。 100% 商业闭源安全嵌入，零 CGO、零外置运行时依赖。
校准与兼容知识库
ClearlyDefined · OSADL Matrix		 ClearlyDefined: CC0-1.0
OSADL Matrix: CC-BY-4.0		 NOASSERTION 坐标自动救回 + 机器可读双向兼容性真值表。 ClearlyDefined 零负担；OSADL Matrix 须在产品 NOTICE 保留归属署名。
Tier 2 深度扫描与模板
ScanCode-Toolkit · ORT		 代码：Apache-2.0
LicenseDB：CC-BY-4.0		 异步容器逐文件抓取版权/夹带条款（ScanCode），借鉴 ORT curations.yml 与 PlainTextTemplate。 严禁引入 FOSSology（GPL-2.0-only）；ScanCode LicenseDB 须履行 CC-BY-4.0 署名。
THIRD-PARTY-NOTICES 自动化交付 合规输出规范 ① 按 Scope 剔除 dev/test；② 按 OR 选定分支裁剪；③ 许可证全文去重汇总版权。 Apache-2.0 §4(d) 硬要求：必须采集并原样透传包内 META-INF/NOTICE* 文件，为 LGPL/MPL 附 Written Offer。
