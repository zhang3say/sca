Agentic AI 与 MCP 服务器供应链治理（OWASP ASI04）

在 Lesson 0006 中，我们把自家 SCA 引擎打包成了保护 Coding Agent 的 MCP Server；但今天硬币的另一面正在成为企业最失控的盲区：研发本地与生产环境装满了来自 GitHub、npm 和社区注册表的第三方 MCP Server 与 SKILL.md 智能体技能包。根据 OWASP Top 10 for Agentic Applications 2026，ASI04: Agentic Supply Chain Vulnerabilities 已正式将工具定义投毒（Tool Poisoning）、动态篡改（Rug Pull）、跨服务劫持（Tool Shadowing）与无版本锁定启动（npx -y）列为智能体头号供应链威胁。本课为你收官 Chapter 05 与 Phase 2，构建可纳入统一 SCA 台账与策略网关的 Agentic 治理体系。

本课收获：吃透 OWASP ASI04 与 MCP 规范安全边界（tools/list_changed、untrusted annotations、OAuth 2.1 + RFC 8707）；复盘 TPA、Rug Pull、postmark-mcp、CVE-2025-49596 与 CVE-2025-6514；划清 toolhive / mcp-gateway / agentgateway / mcp-scanner / agent-scan 商用数据主权边界并落地 Pure Go 钉死与语义审计原语 先修底座：Lesson 0006 · Lesson 0015 · Lesson 0017
架构师核心命题（对齐你的 MISSION.md 与 Phase 2 收官定位）

传统 SCA 只盯住代码里的 package.json 和 requirements.txt，却看不见项目根目录 .mcp.json 里那句 npx -y some-mcp-server、看不见 SKILL.md 里隐藏的提示词外联指令、更看不见远端 MCP 深夜动态推送的一次 tools/list_changed 投毒。只有将 MCP Server（软件依赖 + 传输端 CVE）+ Tool Schema 指纹（防 Rug Pull）+ SKILL.md 自然语言规则（Markdown as Code） 统一纳管到 Layer 2 IR 与零信任网关，你的第三代 SCA 才真正配得上“全场景 AI 时代供应链安全底座”！

01OWASP ASI04 与 MCP 协议的三大结构性信任漏洞

1.1 为什么“人类不可见、模型全信任”造就了全新供应链攻击面？

与传统软件函数调用不同，MCP 客户端在连接一个服务器时，会调用 tools/list 拉取每个工具的名称、JSON 参数 Schema 与自然语言 description，并将其原封不动拼接进大模型的 System / Tool Context。界面通常只向人类展示简短的工具名或摘要，但大模型却把整段自然语言描述当作可信操作指令来执行。

2025 年 4 月，Invariant Labs 首次系统演示了针对 MCP 生态的三类“零漏洞代码执行”供应链攻击；随后在 2025 年下半年，npm 在野恶意 MCP 包与官方/热门代理组件的 RCE CVE 接连爆发，彻底引爆了 OWASP ASI04（Agentic Supply Chain Vulnerabilities）。

MCP 官方规范明文写明的“不可信标注”条款 MCP Tool 对象支持 annotations（如 readOnlyHint、destructiveHint、idempotentHint、openWorldHint）。规范明确规定：
• Clients MUST treat tool annotations as untrusted unless they come from a trusted server.
• 恶意 MCP 完全可以把删库工具标成 readOnlyHint: true；若客户端据此自动跳过用户确认框，就构成了典型的协议级权限欺骗。
攻击载体 / 真实事件 利用的协议或供应链缺陷 攻击链与现实危害 SCA / 网关核心拦截锚点
Tool Poisoning (TPA)
（Invariant Labs · 2025.04）		 tools/list 描述字段混入隐形指令（<IMPORTANT>）与隐藏参数 表面是 add 算术工具，描述内却要求 Agent 读取 ~/.ssh/id_rsa 与 .env 塞入 sidenote 参数悄悄外传。 本地静态扫描工具描述语义与隐藏标签/敏感路径模式，拒绝把带毒 Schema 注入 LLM Context。
MCP Rug Pull
（动态热变脸）		 notifications/tools/list_changed 动态刷新工具定义 初审和用户授权阶段完全清白；待建立长期信任后，服务端推送列表变更通知，静默替换恶意描述且免二次审批。 首次入库对完整 Tool JSON Schema 计算 SHA256 Pinning；一旦漂移立即熔断冻结并强制重审。
Cross-Server Tool Shadowing
（跨服务劫持 · WhatsApp 演示）		 同会话多 MCP 共用单个 LLM 上下文窗口 恶意 MCP 根本无需被直接调用，只需在描述里指令 Agent“每次用受信任的 WhatsApp/邮件 MCP 时暗中转发聊天记录”，绕过传统 DLP。 跨服务指令引用检查 + 单工具禁止提及或改写其他 MCP Server 行为 + 出站目标白名单策略。
postmark-mcp 在野投毒
（npm · 2025.09 · 1.0.16–1.0.18）		 首个在野恶意 MCP Server npm 包 + npx -y 自动拉最新版 在合法发信 MCP 更新版本中植入 1 行暗桩，向 Agent 发出的每封邮件静默添加 BCC 抄送攻击者邮箱，窃取密码重置与发票。 严禁 .mcp.json 中写 npx -y 无锁版本；联动 Lesson 0015 MAL-* 与 Capability Diff 拦截。
CVE-2025-49596 & CVE-2025-6514
（端侧组件 RCE）		 MCP Inspector <0.14.1 无鉴权 / mcp-remote 0.0.5–0.1.15 命令注入（CVSS 9.6） 网页 DNS Rebinding 即可打穿本地 Inspector 执行 stdio 命令；连接恶意远端 MCP 时特制授权 URL 直接触发本机 OS 命令注入。 Layer 1 端侧资产采集器必扫开发机 MCP 运行时与代理包版本，强制升级 Inspector ≥0.14.1 与 mcp-remote ≥0.1.16。
SKILL.md + npx -y 组合链
（Markdown as Code）		 Agent 把 SKILL.md / CLAUDE.md / AGENTS.md 当作可执行流程记忆 恶意技能文档诱导 Agent 运行恶意 Shell 或配合未钉死的 .mcp.json 启动恶意工具，以开发者完整宿主权限窃密。 将技能 Markdown 纳入代码级 PR 审查与提示注入扫描，stdio 强制容器化并绑定不可变 Digest。

02全触点盘点、Layer 2 IR 扩展与 OAuth 2.1 / RFC 8707 零信任网关

2.1 从 Layer 1 配置文件发现到 Layer 2 Tool Pinning 图谱建模

要把 Agentic AI 供应链真正管起来，你的 SCA 平台必须在 Layer 1（IDE / Repo / 终端盘点） 识别开发者机器与代码仓里的所有 Agent 扩展入口，并映射到 Layer 2 统一 IR：

  • Layer 1 采集目标文件清单：项目级 .mcp.json、.cursor/mcp.json、.vscode/mcp.json、桌面端 claude_desktop_config.json，以及技能指令文件 SKILL.md / CLAUDE.md / AGENTS.md。
  • Layer 2 IR 节点与属性扩展：新增 MCP_SERVER（记录传输方式 stdio/streamable-http、底层依赖 PURL 如 pkg:npm/... 或容器 Digest）、MCP_TOOL（记录规范化 JSON Schema 的 tool_schema_sha256 指纹）与 AGENT_SKILL（记录技能文件 SHA256 与声明所需工具权限集合）。
  • 远端 HTTP 鉴权刚性基线（MCP Authorization Spec）：所有远端 HTTP MCP Server 必须采用 OAuth 2.1 + PKCE，且客户端在授权和 Token 请求中必须携带 RFC 8707（Resource Indicators）resource 参数绑定目标服务器规范 URI，防止 Access Token 被恶意中间服务器转发透传（Token Passthrough）或引发跨服务混淆代理人攻击。
本地 stdio 最大失控点：秘密全裸暴露 当研发在 .mcp.json 的 "env" 字段明文写满 GITHUB_TOKEN、AWS_SECRET_ACCESS_KEY 或数据库连接串直接喂给一个未知第三方 Node/Python MCP 进程时，该进程拥有与宿主完全一致的环境变量读取权和出网权限。零信任网关的核心价值之一就是进程外凭证代管 + 按需最小路径/网络策略隔离。

3.1 商用闭源底座整合：既要查 SPDX 协议，更要守住“数据主权红线”

与常规 SCA 组件不同，MCP 安全扫描器往往不仅涉及源码许可证，还涉及一个隐形商业雷区——是否把企业客户的内部 Tool Schema 与业务提示词静默回传给外部云端检测 API。下表逐一核验主流开源项目的精确协议与整合边界：

stacklok/toolhive Apache-2.0 面向开发机与集群的 MCP 容器封装器：自动把裸跑 stdio 关进受限容器、托管密钥注入与网络策略，并内置校验门禁。 极佳集成/对标底座：Apache-2.0 纯宽松，Go 技术栈与本课程底座高度同构，适合作为本地/网关侧沙箱化运行时参照。

3.2 Pure Go 核心原语：.mcp.json 版本锁校验 + Tool Schema SHA256 Pinning

下面这段 Pure Go 原语可以直接嵌入你在 Lesson 0006 设计的三模本地 SCA 核心（--mode=hook / --mode=mcp），在 5 毫秒内同时拦住 npx -y 未锁版本启动、Tool Rug Pull 哈希漂移与 TPA 隐藏敏感指令：

Go 核心原语：.mcp.json 启动锁校验、Tool Schema SHA256 Pinning 与本地 TPA 启发式审计 Zero-Cloud-Leak Pure Go Agentic 供应链守护内核 
type MCPToolDef struct {
    Name        string         `json:"name"`
    Description string         `json:"description"`
    InputSchema map[string]any `json:"inputSchema"`
    ReadOnly    bool           `json:"-"` // 规范强制：绝不可轻信服务端 annotations.readOnlyHint
}

var tpaPattern = regexp.MustCompile(`(?i)(<IMPORTANT>|do not mention|~/.ssh|\.env\b|send_whatsapp|bcc\s*=|sidenote)`)
var pinnedPkgRe = regexp.MustCompile(`^(@[a-z0-9-]+/)?[a-z0-9._-]+@\d+\.\d+\.\d+`)

// AuditMCPServerLaunch 拦截危险的 npx -y / uvx 无版本钉死裸跑配置
func AuditMCPServerLaunch(cmd string, args []string) error {
    if cmd == "npx" || cmd == "uvx" {
        for _, a := range args {
            if strings.HasPrefix(a, "-") { continue }
            if !pinnedPkgRe.MatchString(a) {
                return fmt.Errorf("blocked ASI04: unpinned dynamic launch %s %q", cmd, a)
            }
            break
        }
    }
    return nil
}

// VerifyAndPinTool 校验工具描述语义并对比入库基线 SHA256，防止 Rug Pull 与 TPA
func VerifyAndPinTool(tool MCPToolDef, expectedSHA string) (currentSHA string, err error) {
    if tpaPattern.MatchString(tool.Description) {
        return "", fmt.Errorf("blocked TPA/Shadowing indicator in tool %q description", tool.Name)
    }
    canonical, err := json.Marshal(tool) // 生产需保证 map key 规范序序列化（RFC 8785 JCS）
    if err != nil {
        return "", err
    }
    sum := sha256.Sum256(canonical)
    currentSHA = hex.EncodeToString(sum[:])
    if expectedSHA != "" && currentSHA != expectedSHA {
        return currentSHA, fmt.Errorf("blocked RUG_PULL: tool %q schema hash drifted (%s != %s)", tool.Name, currentSHA[:12], expectedSHA[:12])
    }
    return currentSHA, nil
}
