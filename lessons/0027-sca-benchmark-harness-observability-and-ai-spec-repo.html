AI 协同质量防线：SCA 黄金样本回归评测、OTel 剖析与 Monorepo/Spec 落地

这是专为 「1 人总架构师 + AI Coding Agents」 准备的收官工程保险。AI 可以用 10 分钟帮你重构 Maven BOM 解析器或重写 Pickle 操作码校验，但如果只靠几十条单元测试，一次“看似全绿”的修改就可能悄悄让全站 Recall 暴跌 15% 而你毫无察觉。本课拍板三道终极护栏：SCA 黄金样本 Benchmark Harness（精度与延迟硬门禁）、OpenTelemetry 跨语言 Span 剖析、以及「单一契约真值」Monorepo 与 90 天垂直切片 MVP 落地蓝图。

本课收获：建立不让 AI 静默改坏 SCA 精度的黄金评测基准（Precision/Recall/F1/P95）；用 OpenTelemetry（Apache-2.0）串通 Go↔Python 全链路性能归因；带走可直接建仓的 Go+Python+Proto+oapi-codegen Monorepo 骨架与 90 天垂直切片节奏 前置关联：Lesson 0008 (版本比较) · Lesson 0024 (Go↔Python 契约) · Lesson 0026 (双模交付)
Solo + AI Agent 最致命的幻觉：“单元测试全绿 = SCA 引擎没改坏”

SCA 引擎处理的是成千上万个真实开源仓库的边角语义（Maven `import` BOM、Debian Epoch、npm Hoisting、Python Pickle 变种绕过）。AI Agent 在修复某个局部 Bug 时，非常容易通过简化分支条件“凑绿”单测，却导致真实世界的误报或漏报激增。把真实世界样本的 Precision / Recall 评测变成不可绕过的 CI 闸门，是一个人敢放手让 AI 全速编码的前提条件。

01SCA 黄金样本回归评测基准（Benchmark Harness）

1.1 四维评测黄金数据集（Golden Corpus）怎么建？

你不需要第一天就攒几万个仓库；从 80–150 个精心挑选的高信噪比真实样本（涵盖每类陷阱至少 5 个固定 Commit Snapshot 与人工校对 Ground Truth）起步，就能拦住 95% 的 AI 回归事故：

黄金集必须独立于 AI 改代码的测试目录 把黄金集 Manifest 与 Ground Truth 放进受保护的 eval/golden-corpus/ 目录并配置 CODEOWNERS / Spec 锁死——绝不允许 AI Agent 在跑不通过时顺手去修改预期答案（Ground Truth）来“凑绿”！
黄金样本测试象限 样本构成与真实陷阱覆盖 强制卡死的量化门禁指标 典型防 AI 事故示例
1. L1 依赖提取象限
（源码 + 容器 + 制品）		 覆盖 Maven BOM/Gradle、pnpm Monorepo、Go replace、PEP 508 markers、OCI Whiteout 层与 Distroless。 组件 PURL Precision ≥ 99.0%；Recall ≥ 98.0%；直接/传递边准确率。 拦住 AI 重构依赖树遍历时丢失多层 BOM 覆写或忽略删除层标记。
2. L3 版本与 Backport 象限
（匹配零误差）		 覆盖 SemVer 预发布、Debian ~/Epoch、RPM ^、Backport 隔离（CVE-2024-6387）与 VERS 合并。 误报回退 = 0；漏报回退 = 0（任何既有确定病例出错即 Fail）。 拦住 AI 误用通用字符串比大小替换生态原生比较器。
3. L4 可达性与投毒象限
（护城河指标）		 Go/Java/JS/Python 带真实调用链与未调用孤岛样本；恶意包变种与 Pickle/NullifAI 载荷样本。 可达性降噪比（Noise Reduction）& 恶意载荷 Recall 零下降（严守 Fail-Closed）。 拦住 AI 为提升速度把 Pickle 白名单偷偷放宽导致 RCE 样本逃逸。
4. 性能与 P95 预算象限
（防尾部劣化）		 1 个中型 Monorepo（~2,000 依赖）+ 1 个多层容器镜像的端到端延迟压测。 PR 快路径 P95 < 15s；内存峰值不超私有化 4C8G 容器上限。 拦住 AI 写出 `O(N^2)` 图递归或无界正则回溯导致线上 OOM。

02OpenTelemetry 跨语言（Go ↔ Python）全链路耗时剖析

2.1 用一条 traceparent 贯穿单次扫描的真实瓶颈，不再盲猜优化

当客户抱怨“为什么这次扫描花了 45 秒？”时，不要拍脑袋优化 Go 循环——真实瓶颈往往藏在某个跨语言调用、镜像层解压或数据库锁等待里。借助 CNCF OpenTelemetry（opentelemetry-go 与 opentelemetry-python，均 Apache-2.0）与 W3C Trace Context 规范，在每次扫描创建时生成唯一 TraceID：

  • HTTP / ConnectRPC 自动注入 traceparent 头：Go 控制面调起 Python AI-BOM Worker 时自动透传上下文，同一张火焰图直接展现 Go L1 提取、ConnectRPC 传输、Python Safetensors 解析、Go L3 匹配与 PG WithTenantTx + Outbox 的精确毫秒数占比。
  • 结构化业务属性（Span Attributes）：在 Span 上挂载脱敏维度 sca.tenant_id、sca.asset_kind、sca.lane (interactive|batch)、sca.cache_hit (cas)，绝不记录用户源码片段或敏感凭证。
  • 双模零运维观测后端：SaaS 导出至任意兼容 OTLP 的观测平台；极简私有化模式下仅输出结构化 JSON Trace/Metrics 日志或单二进制采集器，不强制客户运维整套重型监控集群。
给关键核心指标加 3 条 Prometheus Histogram sca_scan_duration_seconds{lane,kind}、sca_queue_lag_seconds{lane}、sca_outbox_pending_rows。仅这 3 个指标就能在 30 秒内判定系统是卡在扫描器 CPU、Python 队列积压还是 PG 出站同步。

03AI 友好的「单一契约真值」Monorepo 与 90 天垂直切片蓝图

3.1 Monorepo 目录与「生成代码只读禁手改」规则

为了最大化发挥 AI Coding Agent 的全局视野并根除前后端/跨语言联调幻觉，强烈推荐采用 单一契约真值（Single-Source-of-Truth Codegen）Monorepo：

  • contracts/（人工与 AI 唯一可改的接口源头）：包含 proto/（经 Buf 生成 Go & Python ConnectRPC 代码）、openapi.yaml（OpenAPI 3.1，经 oapi-codegen Apache-2.0 生成 Go 强类型服务端/SDK 与前端 TypeScript 类型）、以及 db/queries/*.sql（经 sqlc MIT 生成 Go DAO）。
  • 生成产物目录标为 Generated Read-Only：在 AGENTS.md / CLAUDE.md 中明确约定：禁止 AI 手改任何 gen/ 生成代码；改接口必须先改契约再跑 make generate。
  • docs/adr/（MADR 轻量决策记录）+ spec/：每次拍板重要架构取舍（如为什么选 Valkey 替 Redis、为什么选 PG RLS），留下一页 MADR，让未来的自己与新开对话的 AI Agent 瞬间继承完整上下文。
前 90 天（M1–M3）垂直切片原则 不要第一个月全写数据库表、第二个月全写扫描器、第三个月才联调界面！按月垂直切出“端到端可演示、可签单、可跑双模”的闭环切片，每月都能真刀真枪拿去跑客户 POC。
