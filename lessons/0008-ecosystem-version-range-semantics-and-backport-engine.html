生态原生版本区间语义引擎：SemVer、Maven、PEP 440、Debian EVR 与 VERS

拿到 Lesson 0007 的干净 canonical_match_rules 后，最容易让架构师掉以轻心的一句话是“不就是比版本号大小吗？”。现实是：把所有生态硬转成 SemVer、拿包管理器的选包 Specifier 当漏洞匹配器、或跨命名空间比对发行版 Backport 版本，上线当天就会制造系统性的静默漏报与误报风暴。

本课收获：划清「全序比较器 vs 选包约束」边界，吃透 6 大生态原生排序暗坑、vers: 规范化与 Backport 彻底隔离架构 先修底座：Lesson 0005 · Lesson 0007
承上启下（对齐你的 Mission）

在 Lesson 0007 中，canonical_match_rules 表把漏洞影响范围收敛成了标准化的 range_type (SEMVER | ECOSYSTEM | GIT)、events_json 与 distro_qualifier。本课要拍板消费这张规则表的核心计算引擎——如何在 Go 核心中科学整合 osv-scalibr/semantic、grype/version 等 Apache-2.0/MIT 比较器，自研 vers: 规范化器，并在引擎层彻底封死发行版 Backport 误报。

01第一原则：彻底分离「全序比较器」与「选包约束（Specifier）」

许多工程团队写 Layer 3 匹配引擎时，图省事直接把待测依赖版本丢进生态现成的范围求值库——例如 Node 侧直接调 node-semver 的 semver.satisfies(ver, "<1.2.4")，Python 侧直接调 packaging.specifiers.SpecifierSet("<1.0.0")。这是极其危险的语义错配！

原因在于依赖解析（Layer 1 / Layer 4）与漏洞区间求值（Layer 3）遵循两套完全不同的数学假设：

  • 包管理器 Specifier（防意外升级不稳定版）：根据 npm/node-semver 预发布规则，如果一条范围里没有任何比较子带预发布标签且拥有相同的 [major, minor, patch] 元组，所有预发布版本一律被拒绝匹配。Python PEP 440 更严格：SpecifierSet("<1.0.0") 即使显式传入 prereleases=True，对 1.0.0a1 依然返回 False（因为按 PEP 440 排他比较定义，<V 禁止匹配属于 V 发布周期的预发布版）。
  • 漏洞区间 Comparator（全序覆盖一切已运行代码）：依据 OpenSSF OSV Schema，SEMVER 与 ECOSYSTEM 区间必须基于该生态的全序关系（Total Order）求值。只要系统里装了 1.2.4-alpha.1 或 1.0.0a1，且漏洞直到正式版 1.2.4 / 1.0.0 才修复（即全序满足 introduced ≤ v < fixed），该预发布包同样存在漏洞！
Go 模块 semver 的两个细节 Go 官方库 golang.org/x/mod/semver（BSD-3-Clause）强制要求版本号带小写 v 前缀（如 v1.2.3），而 OSV SEMVER 规范恰好禁止带 v 前缀——适配器边界必须做统一校验补全。此外，按 Go Modules Reference，伪版本（v0.0.0-20200101000000-abcdef）按 SemVer 预发布时间戳自然排序，+incompatible 在 SemVer 排序中则等同构建元数据被忽略（v2.0.0+incompatible == v2.0.0），仅用于标识无 go.mod 的 v2+ 仓库路径。
架构师硬约束：L1/L4 与 L3 双引擎接口分离

自研平台内核必须显式拆出两个接口，严禁混用：Comparator.Compare(eco, a, b) → {-1, 0, 1} 专供 Layer 3 漏洞区间求值与 vers: 化简；Specifier.Satisfies(eco, v, constraint) 专供 Layer 1 依赖树求解与 Layer 4 自动升级规划。此外，OSV events[] 的上界有两种截然不同的闭开语义——fixed 是开区间上界（<），而 last_affected 是闭区间上界（≤）。

02六大主流生态原生排序暗坑与 Token 算法拆解

没有“通用版本号算法”。不同包管理器的历史演化决定了它们对字母、标点、数字和修订后缀截然相反的排序哲学。任何试图用正则剥掉后缀再转成 major.minor.patch 比较的通用库，都会在下面的边界案例中全线翻车：

Maven 未知后缀与 Debian vs RPM 反转 同一组版本 1.0.beta vs 1.0.1：在 RPM rpmvercmp 中 数字段永远压倒字母段（1.0.beta < 1.0.1），而在 Debian dpkg 中空非数字段早于字母段（实测 1.0.1 < 1.0.beta）！而在 Maven 中，1.0.0-redhat-00001 这类未知修饰符竟排在正式版 1.0.0 之后！

03VERS 规范化与发行版 Backport 消误报工程闭环

3.1 VERS（vers:）标准与三条规范化铁律

当 Layer 2 需要通过 CycloneDX 1.7 的 versionRange 或 vulnerabilities[].affects[].versions[].range 交换区间，或自研引擎需要把不同来源的区间统一化简存储时，应遵循 Package-URL 社区制定的 VERS（Version Range Specifier）规范：

语法形态为 vers:<versioning-scheme>/<constraint1>|<constraint2>|...（例如 vers:npm/>=1.0.0|!=1.2.3|<2.0.0 或全集 vers:pypi/*）。工程上编写自研 VERS 规范化器必须守住三条规范铁律：

  1. 零空白符：严格形式禁止任何空格或制表符（必须是 !=1.2.3，不可写 != 1.2.3）。
  2. 按生态全序升序排列：管道符 | 分隔的每个约束子句，必须先用该生态原生 Comparator 按版本号从小到大排序。
  3. 版本唯一性与区间化简（Canonical Simplification）：同一个版本号在一条 VERS 串中只能出现一次（禁止同时出现 >=1.0.0 与 !=1.0.0），重叠或相邻区间须先合并化简为唯一标准形式，才能做缓存键去重与高效求值。
开源唯一参考标杆：univers AboutCode 团队维护的 aboutcode-org/univers（Apache-2.0 AND BSD-3-Clause AND MIT）是目前开源界对 VERS 区间合并化简（VersionRange.normalize()）实现最完整的 Python 库，非常适合作为我们编写纯 Go 版本区间化简器的算法蓝本。

3.2 根除发行版 Backport 误报/漏报：为什么不能跨命名空间比对？

以真实的高危漏洞 OpenSSH CVE-2024-6387（regreSSHion） 为例，该漏洞在 8.5p1 被重新引入、并于 9.8p1 修复（现代分支受影响区间为 [8.5p1, 9.8p1)）。看看如果直接把 Linux 发行版软件包拿去比对上游区间，会同时引爆多么荒谬的误报与漏报双重灾难：

  • 陷阱 A · 剥离 Epoch 硬比上游（误报）：Debian 12 已在 DSA-5724-1 中将补丁回溯（Backport）合入 1:9.2p1-2+deb12u3；RHEL 9 已在 RHSA-2024:4312 中修复至 8.7p1-38.el9_4.1。如果剥去发行后缀按上游版本比，9.2p1 < 9.8p1、8.7p1 < 9.8p1，所有已打补丁的容器全线误报！
  • 陷阱 B · 带着 Epoch 硬比上游（灾难级漏报！）：Debian 的 openssh 带有 Epoch = 1（1:9.2p1-2+deb12u1，一个尚未修复的易受攻击老包），而上游 9.8p1 的隐式 Epoch 为 0。按 EVR 规则 1:9.2p1 > 0:9.8p1——未修补的高危服务器会被静默放行！
RHEL CSAF VEX 的行业标杆转向 Red Hat 已将安全公告主力切换至 CSAF VEX 文档：直接按每个 RHEL 小版本分支（如 rhel-9.4）精确列出每个 CVE 对应的 fixed RPM NEVRA 与 not_affected 判定（如 RHEL 8 的 8.0p1 本就不含 8.5p1 引入的缺陷），彻底绕开上游版本号纠缠。

type VersionComparator interface {
    // Compare 实现生态原生全序比较 (-1, 0, +1)，禁止使用包管理器 Specifier 语义
    Compare(a, b string) (int, error)
}

func MatchComponent(comp IRComponent, rules []CanonicalMatchRule) []Finding {
    // 1. OS 发行版强制走 Distro Backport 隔离轨，严禁匹配无 distro_qualifier 的上游规则
    if comp.IsDistroPackage() {
        return evalDistroBackportRules(comp.SourcePkgName, comp.Version, comp.DistroQualifier, rules)
    }
    // 2. 应用语言包按 PURL Type 路由到对应生态 Total-Order Comparator
    cmp := Registry.MustGetComparator(comp.PurlType)
    var hits []Finding
    for _, r := range rules {
        if !r.IsEnabled || r.RuleScope != "UPSTREAM_PKG" { continue }
        if evalOSVEvents(cmp, comp.Version, r.Events) { // introduced <= v && (v < fixed || v <= last_affected)
            hits = append(hits, NewFinding(comp, r))
        }
    }
    return hits
}
