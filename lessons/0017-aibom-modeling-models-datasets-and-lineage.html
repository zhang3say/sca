AI-BOM 统一建模：模型权重、数据集与推理框架血缘

从本课起我们正式切入 AI 时代软件供应链安全（Lessons 0017–0019）。在传统业务应用中，风险几乎全部落在代码包与基础镜像里；但在大模型与智能体系统中，一个看似全部依赖 Apache-2.0/MIT Python 库的服务，可能因为拉取了 @main 可变分支的模型权重、合并了继承自 Llama 3 的第三方 LoRA 适配器，或者在训练链路混入了 CC-BY-NC-4.0 数据集而直接触发商业禁令与 OWASP LLM03:2025 供应链灾难。本课带你把 AI-BOM 无缝融进现有的 Layer 2 统一 IR 图谱，并吃透 CycloneDX 1.7 ML-BOM 与 SPDX 3.0.1 AI/Dataset Profiles 双标准投影。

本课收获：掌握 pkg:huggingface (ECMA-427) 大小写与不可变 SHA 规范；吃透 CycloneDX 1.7 modelCard vs SPDX 3.0.1 ai_AIPackage/trainedOn 双向映射；落地“不加载权重”的只读头采集（PEFT / GGUF / Safetensors / CNCF ModelPack）；看清 Llama 3、OpenRAIL-M 与 EU AI Act Art. 53 合规门禁 先修底座：Lesson 0002 · Lesson 0010
架构师核心命题（对齐你的 MISSION.md）

我们早在 Lesson 0002 就拍板过：AI-BOM 绝不能另起一套孤立的“模型台账系统”，而必须作为原生节点与血缘边直接长在 Layer 2 统一图谱（IR）之上！只有当「推理容器镜像 → Python vllm/torch 依赖 CVE → 基座模型权重 SHA → LoRA 适配器继承链 → trainedOn 数据集许可」处于同一张图里时，你的 SCA 平台才能一次性回答 CISO 与法务的终极追问：“上线这个 AI 服务究竟有哪些代码 CVE、哪些权重要求、以及是否违反非商用数据条款？”

01为什么传统代码 SBOM 对 AI 应用失明？—— OWASP LLM03:2025 与四维血缘

1.1 AI 应用的真实 BOM 半径：从代码包延伸到权重、适配器与语料

按照 OWASP Top 10 for LLM Applications（LLM03:2025 Supply Chain），生成式 AI 的供应链攻击面已经突破传统第三方库，扩展为相互耦合的四维资产图谱：

  • ① 基座模型（Base Model）：如 Qwen/Qwen2.5-7B-Instruct 或 meta-llama/Llama-3.1-8B-Instruct，体积达数 GB 至数百 GB，承载核心架构与基础许可约束。
  • ② 参数高效微调适配器（PEFT / LoRA Adapter）：体积仅几十 MB，通过低秩矩阵叠加或合并进基座模型——它既可能悄无声息地破坏安全对齐（Alignment），又会在许可层面强制继承基座条款。
  • ③ 训练、微调与评测数据集（Datasets）：决定模型能力边界、潜在投毒/偏见以及商业版权清洗义务（如 CC-BY-NC-4.0 非商用或版权 TDM 保留）。
  • ④ 推理引擎与序列化运行时：如 PyTorch、vLLM、ONNX Runtime、llama.cpp 等传统软件栈（对应我们 Phase 1 已覆盖的 Python/C++ CVE 与依赖图）。
ECMA-427 pkg:huggingface 极易踩错的大小写规范 在 package-url/purl-spec（ECMA-427） 中，Hugging Face 模型与数据集使用 pkg:huggingface/<namespace>/<name>@<version>：
• namespace 与 name 严格区分大小写（如 Qwen/Qwen2.5-7B-Instruct 不可强行小写）；
• version 为 Git Commit Hash 时必须统一转为小写，私有镜像站通过 ?repository_url=... 表达；
• 安全铁律：生产 AI-BOM 严禁使用可变分支名（如 @main），必须强制钉死 40 位十六进制 Commit SHA！

1.2 在 Lesson 0002 Layer 2 统一 IR 上扩展 AI-BOM 节点与血缘边

延续 Lesson 0002 的 PostgreSQL / 图谱设计，Layer 2 IR 只需引入三类 AI 一等实体与四条有向关系边即可实现与传统软件依赖图完全同构的查询与合规推理：

  • 扩展节点类型（component_type）：MODEL_WEIGHT（基座或合并权重）、PEFT_ADAPTER（LoRA/QLoRA 适配器）、DATASET（训练/验证数据集），统一通过 PURL（如 pkg:huggingface/...）+ 内容 SHA256 双层标识去重。
  • 扩展有向血缘边（edge_type）：ADAPTS（适配器指向基座模型）、DERIVED_FROM（微调/量化 GGUF 模型溯源）、TRAINED_ON / TESTED_ON（模型或微调任务指向数据集）、SERVED_BY（AI 模型关联推理容器与 vllm/torch 运行库）。

02双国际标准深度对标：CycloneDX 1.7 ML-BOM vs SPDX 3.0.1 Profiles

2.1 工程视角看清两大标准的结构差异与双向投影规则

与软件 SBOM 领域相同，商业 SCA 平台必须坚持“内部 Layer 2 IR 主权 + 对外同时无损导出 CycloneDX 1.7 与 SPDX 3.0.1”。但两大标准对 AI 资产的抽象方式差异显著，绝不能混淆字段位置：

CycloneDX 1.7 Schema 强制约束 在官方 bom-1.7.schema.json 中，modelCard 对象仅当组件 type 为 "machine-learning-model" 时才允许出现（MUST NOT 用于普通软件库或硬件组件）。数据集则必须建模为独立的 type: "data" 组件（携带 data 数组），再由 modelCard.modelParameters.datasets 通过 bom-ref 指向它。
建模维度 CycloneDX 1.7 ML-BOM（ECMA-424） SPDX 3.0.1 AI & Dataset Profiles
底层图结构范式 组件中心树 + dependencies[] 引用；模型资产内嵌完整 modelCard 元数据块。 扁平 JSON-LD @graph 图模型；元素与关系完全解耦，所有关联由一等公民 Core_Relationship 节点表达。
AI 模型核心对象 components[].type = "machine-learning-model" + modelCard.modelParameters（approach.type / task / architectureFamily / modelArchitecture）。 ai_AIPackage（/AI/AIPackage 类），原生包含 ai_autonomyType、ai_domain、ai_energyConsumption、ai_limitation 等字段。
数据集核心对象 components[].type = "data" + data[]（定义类型、内容描述、治理与清洗属性）。 dataset_DatasetPackage（/Dataset/DatasetPackage），含 datasetType、dataCollectionProcess、dataPreprocessing、knownBias、anonymizationMethodUsed。
训练 / 评测血缘表达 modelCard.modelParameters.datasets[] 引用数据集 bom-ref，并在 dependencies 表达图依赖；quantitativeAnalysis 记录评估指标。 严格使用独立 Core_Relationship 节点，relationshipType 规定必须采用精确词表 trainedOn 或 testedOn。
商业平台主攻定位 工程安全与 DevSecOps 交付首选：天然集成 VEX、citations 溯源与 cdxgen（Apache-2.0）生态。 跨国合规、欧盟 AI 法案审计与法务交付首选：数据集偏见/脱敏元数据与精确有向关系粒度最细。

03无加载元数据采集、非 OSI 许可治理与 Go 核心原语

3.1 毫秒级“不加载权重”采集锚点与 OCI ModelPack 生态

在现代 ML 工程仓库与推理镜像中，模型文件动辄几十 GB。优秀的 Layer 1 AI-BOM 采集器绝不能把整块权重塞进显存或调用 pickle.load()，而应精准读取以下 5 类轻量元数据头与 OCI 制品清单：

AI 制品形态 精确文件 / 字节头锚点 提取的核心血缘与配置字段 工具底座与许可边界
Hugging Face 模型仓 config.json & README.md YAML Frontmatter architectures（如 LlamaForCausalLM）、model_type、license、datasets[]、base_model[]。 纯 HTTP/Git 树只读拉取（对齐 pkg:huggingface ECMA-427）。
PEFT / LoRA 适配器 adapter_config.json base_model_name_or_path（基座溯源锚点）、peft_type、r、lora_alpha、target_modules。 纯 JSON 解析，无条件触发向基座模型许可的继承追溯。
GGUF 本地量化权重 二进制文件魔数 GGUF 后的 KV 元数据头 general.architecture、general.name、general.license、general.quantization_version。 流式只读前几十 KB Header 即可（参考 ggml 规范）。
Safetensors 权重 前 8 字节 uint64 长度 + UTF-8 JSON Header __metadata__（含微调来源、训练框架标签与张量 dtype/shape 校验）。 零代码执行、只读 Header JSON 即可，无需映射全量张量体。
OCI 模型制品包 CNCF ModelPack / KitOps Kitfile OCI Manifest Annotations 与 model / datasets / code / prompts 分层声明与内容 Digest。 Apache-2.0（modelpack/model-spec 与 kitops-ml/kitops 均纯宽松商用）。

3.2 Go 核心原语：LoRA 继承追溯、不可变 SHA 强制门禁与 EU AI Act 合规

不同于普通软件库在 SPDX 3.0.1 中的标准 OSI 开源协议，大量主流大模型采用自定义非 OSI 社区协议（如 Llama 3 Community License、OpenRAIL-M），且受 EU AI Act Article 53(1)(d)（已于 2025 年 8 月 2 日正式生效，要求进入欧盟市场的 GPAI 模型公开充分的训练数据摘要并披露版权 TDM 退出政策）等监管硬约束。下面用 Pure Go 原语展示如何在 Layer 2/3 内核实现血缘传递与合规门禁：

必须盯紧的 Llama 3.1 商业红线 3 条款 哪怕下游 LoRA 仓库自己写着 MIT，只要基座为 Llama-3.1，就必须受以下 3 条硬约束：
1. 700M MAU 上限：月活超 7 亿须向 Meta 另签商业授权；
2. UI 显著署名：界面/文档必标 "Built with Llama"；
3. 命名与禁训竞品：衍生模型名须以 "Llama" 开头，且严禁用其输出去训练其他大模型！
Go 核心原语：AI-BOM 血缘递归许可继承、SHA 锁定检查与非商用数据集门禁 Pure Go 自研 Layer 2/3 AI 合规推理内核（无缝对接 CycloneDX 1.7 / SPDX 3.0.1） 
type AIAssetKind string
const (
    KindBaseModel AIAssetKind = "MODEL_WEIGHT"
    KindAdapter   AIAssetKind = "PEFT_ADAPTER"
    KindDataset   AIAssetKind = "DATASET"
)

type AIAssetNode struct {
    PURL              string      // pkg:huggingface/<ns>/<name>@<40-hex-sha>
    Kind              AIAssetKind
    DeclaredLicense   string      // 例如 "Apache-2.0", "Llama-3.1", "OpenRAIL-M", "CC-BY-NC-4.0"
    BaseModelRef      string      // 来自 PEFT adapter_config.json 的 base_model_name_or_path
    TrainedOnDatasets []string    // 对应 SPDX 3.0.1 trainedOn 血缘列表
    HasEUArt53Summary bool        // EU AI Act Art. 53(1)(d) 训练数据摘要完备性
}

var hexSha40Re = regexp.MustCompile(`@[0-9a-f]{40}(\?|$)`)

func EvaluateAICompliance(nodeID string, graph map[string]AIAssetNode, mauMillion int, targetEU bool) (allowed bool, obligations []string, blockers []string) {
    visited := make(map[string]bool)
    var walk func(id string)
    walk = func(id string) {
        if visited[id] { return }
        visited[id] = true
        n, ok := graph[id]
        if !ok { return }

        // 1. 强制不可变 SHA 钉死（禁止 @main 等可变分支名）
        if strings.HasPrefix(n.PURL, "pkg:huggingface/") && !hexSha40Re.MatchString(n.PURL) {
            blockers = append(blockers, "mutable_ref_forbidden:"+n.PURL)
        }

        // 2. 非 OSI 许可与数据集传染校验（无论适配器自己宣称 MIT 还是 Apache-2.0，均须沿血缘叠加）
        switch n.DeclaredLicense {
        case "CC-BY-NC-4.0":
            blockers = append(blockers, "non_commercial_taint:"+n.PURL)
        case "Llama-3.1":
            if mauMillion > 700 {
                blockers = append(blockers, "llama_700m_mau_exceeded:"+n.PURL)
            }
            obligations = append(obligations, "UI/文档必标 Built with Llama 且衍生命名须以 Llama 开头")
        case "OpenRAIL-M":
            obligations = append(obligations, "受 OpenRAIL 使用领域限制条款约束，须人工审批上线场景")
        }

        if targetEU && n.Kind == KindBaseModel && !n.HasEUArt53Summary {
            blockers = append(blockers, "missing_eu_ai_act_art53_training_summary:"+n.PURL)
        }

        // 3. 沿适配器基座与 trainedOn 数据集递归向上回溯
        if n.BaseModelRef != "" { walk(n.BaseModelRef) }
        for _, ds := range n.TrainedOnDatasets { walk(ds) }
    }
    walk(nodeID)
    return len(blockers) == 0, obligations, blockers
}
