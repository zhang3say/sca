# 初始基线：具备安全/工程架构背景的 0→1 SCA 产品负责人

学习者具备通用安全与软件工程架构背景，正主导从 0 到 1 打造全场景商业闭源 SCA 产品矩阵，但尚未系统实现过 SCA 内核模块。近期（1–3 个月）首要目标是拍板统一底座架构（多语言依赖解析、PURL/SBOM 图模型、开源引擎整合与漏洞库架构），且受商业闭源交付硬约束（必须规避 GPL/AGPL 等强传染性协议及竞品商用限制条款，偏好 Apache-2.0/MIT）。

## Evidence
用户在课程启动访谈中明确陈述了从 0 到 1 的产品阶段、第一阶段核心聚焦领域、商业闭源协议约束以及“底层原理 + 开源/标杆对标 + 选型权衡”的架构师学习偏好。

## Implications
- 无需铺垫通用软件工程或基础安全概念，可直接切入 SCA 特有的数据结构、协议规范、源码级架构边界与真实工程权衡。
- 必须首先建立「四层解耦与内部 IR 主权」的核心架构心智，防止绿地项目在初期误将开源 CLI 工具当作核心架构而埋下重构债。
- 涉及任何开源项目引入时，必须同步核验并显式呈现其代码与配套规则/数据集的许可证边界。
